# Signal Weekly Owner Editor Guide

This guide is for routine website updates. You do **not** need to edit code or use GitHub for these tasks.

> The public address will remain **`https://www.signrl.com`**. The protected editor is a separate sign-in area used only by the site owner.

## 1. Opening the editor

1. Open the protected editor address provided after the domain move.
2. Sign in with the same Manus account that owns the Signal Weekly project.
3. Select the area you want to update from the left-hand menu.
4. Make your changes, then select **Save changes**.
5. Use **View live site** to check the public page in a new tab.

If you see an access message, do not create another account or share the editor link publicly. Take a screenshot and request help.

## 2. What each editor area controls

| Editor area | Use it for |
|---|---|
| **Landing page** | Site name, headline, introductory wording, hero image, footer wording, and menu labels. |
| **Briefing sections** | The three career-focus cards, archive example, and rotating career prompts. |
| **Resources** | The ATS audit, interview guide, future resources, descriptions, labels and download links. |
| **Links & uploads** | ATS destination, live-training destination, LinkedIn link, and uploads for approved PDFs or images. |

## 3. Uploading a new PDF guide

1. Open **Links & uploads**.
2. Select **Choose file** and select your PDF. Files must be under 10 MB.
3. Wait for the upload confirmation. The site link is copied automatically.
4. Open **Resources**.
5. Paste the new link into the correct guide’s **Download URL** field.
6. Change its status to **Available now** only after checking that the file opens correctly.
7. Select **Save changes**, then use **View live site** to test the public download.

## 4. Updating an ATS or live-training link

1. Open **Links & uploads**.
2. Paste the complete destination address, beginning with `https://`.
3. For live training, leave the field blank until a real event link exists. A blank field does not show a false link to visitors.
4. Select **Save changes**.
5. Use **View live site** and test the button once.

## 5. Safe publishing checklist

Before selecting **Save changes**, check that names and dates are correct, every public link begins with `https://`, each new download opens, unfinished guides are clearly labelled **In development**, and the public wording does not promise job-search outcomes.

After saving, refresh the public page in a private/incognito browser tab. This avoids mistaking an older cached page for the new version.

## 6. Services you will still use separately

| Service | Purpose |
|---|---|
| **Beehiiv** | Subscriber list, confirmation emails, welcome email and newsletter sending. |
| **Porkbun** | The domain registration and rare domain/DNS changes. |

## 7. Do not change these without help

Do not alter the custom-domain settings, delete download files that are still linked publicly, or change the Privacy Policy’s legal operator details without a proper review. These changes can affect the live site, downloads or legal notices.
